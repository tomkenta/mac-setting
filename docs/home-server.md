# Mac mini ホームサーバー設定

家庭内LANでMac miniをヘッドレス運用するための手順。
インターネットへSSHや画面共有のポートを直接公開する構成は対象外とする。

## 1. 自動設定

Mac miniでこのリポジトリを取得し、次を実行する。

```sh
cd mac-setting
./setup-server.sh
```

スクリプトは次を設定する。

- SSH（リモートログイン）を有効化
- SSH接続を実行ユーザに許可（既存の許可ユーザは保持）
- 画面共有を有効化し、実行ユーザに許可
- 本体の自動スリープを無効化
- Wake on LANを有効化
- 停電後の自動起動を有効化
- macOSのアプリケーションファイアウォールを有効化
- 署名済みソフトウェアの受信接続を自動許可
- ステルスモードを有効化
- Tailscale Standalone版をインストールして初回認証を開始
- Node.js 24、n8n、Claude Code、Codex CLIをインストール
- Python 3.12、uv、LangGraphをインストール
- n8nをユーザー権限のLaunchDaemonとして常時起動

インストール対象は`Brewfile.server`に集約する。Homebrewのformula/caskに加えて、
n8nも`npm "n8n"`として管理する。スクリプト内に別のインストール一覧は持たない。
Homebrew Bundleはnpmのインストールスクリプトを省略するため、セットアップでは
n8nのパッケージ内だけでネイティブ依存を再構築してから起動を確認する。
Python依存は`server/requirements.txt`で管理する。

再実行すると同じ設定を適用する。Brewfileの既存パッケージはHomebrew Bundleの
更新方針に従うため、バージョンを固定した環境の再現を保証するものではない。

インストールやOS設定を実行せず、依存一覧・処理順・エラー時の停止を検証するには
次を実行する。

```sh
ruby server/tests/package_setup_test.rb
```

## 2. 画面共有

スクリプトは画面共有を有効化し、実行ユーザを許可グループへ追加する。
実行後、GUIで次の状態を確認する。

1. `システム設定 > 一般 > 共有`を開く
2. `画面共有`がオンになっている
3. アクセスを許可するユーザが管理用アカウントに限定されている
4. `リモートマネージメント`はオフのままにする

別のMacで「画面共有」アプリを開き、`Mac-mini.local`またはIPアドレスへ接続する。

## 3. ネットワーク

- 可能ならWi-FiではなくEthernetを使う
- ルーターのDHCP予約でMac miniのIPアドレスを固定する
- ルーターでTCP 22番や5900番をインターネットへポート開放しない
- 外出先から接続する場合はVPNを使用する

同じLANの別のMacからSSHを確認する。

```sh
ssh -l USER_NAME Mac-mini.local
```

ホスト名はMac miniの`システム設定 > 一般 > 共有 > ローカルホスト名`で確認する。

## 4. 外出先からのアクセス

ルーターのポートは開放せず、Tailscale経由でmacOS標準のSSHと画面共有を利用する。スクリプトがインストールするのは、TailscaleがmacOS向けに推奨しているStandalone版。

1. Mac miniでTailscaleを開き、自分のアカウントでサインインする
2. VPN構成とシステム拡張を許可する
3. 外出先で使うMacまたはスマートフォンにもTailscaleをインストールする
4. 同じtailnetへ接続し、Tailscale管理画面またはアプリでMac miniの名前と`100.x.y.z`形式のIPアドレスを確認する
5. 外出先端末をスマートフォンのテザリングなどへ切り替え、自宅Wi-Fiの外から接続をテストする

通常のSSHクライアントからMagicDNS名またはTailscale IPへ接続する。

```sh
ssh -l USER_NAME MAC_MINI_TAILSCALE_NAME
ssh -l USER_NAME 100.x.y.z
```

画面共有では、接続先にMac miniのTailscale IPを指定する。

Tailscale独自のSSHサーバ機能は使用せず、`リモートログイン`で有効にしたmacOS標準のSSHをTailscaleのネットワーク越しに使う。ルーターでTCP 22番や5900番を開放しない。

### 再起動時の制約

通常のmacOS版Tailscaleはログインユーザとして動作する。停電後にMac miniが再起動してログイン画面で停止すると、Tailscale経由で接続できない可能性がある。この構成の`停電後の自動起動`は本体を起動する設定であり、ログインやTailscale接続の復旧までは保証しない。n8n自体はLaunchDaemonなので、macOSの起動後はユーザーログイン前でも起動する。

完全な無人復旧が必要になった場合は、次のいずれかを別途設計する。

- TailscaleまたはWireGuardに対応したルーターをVPNの入口にする
- macOSのCLI-only `tailscaled`をシステムサービスとして運用する

CLI-only版はTailscaleも経験豊富なmacOS管理者向けとしているため、このスクリプトでは自動導入しない。

## 5. 更新とバックアップ

- `システム設定 > 一般 > ソフトウェアアップデート`でセキュリティ対応とシステムファイルの自動更新を有効にする
- 大型macOSアップグレードは、利用中のサーバソフトウェアとの互換性を確認してから適用する
- 重要なデータをMac mini本体だけに置かず、外付けディスクまたは別の保存先へバックアップする
- サーバアプリが再起動後に自動起動することを確認する

## 6. FileVault

FileVaultは盗難時のデータを保護する一方、再起動後にディスクを解除するまでSSHや画面共有を利用できない場合がある。無人での停電復旧と保存データの機密性を比較して、有効化を決める。

## 7. ヘッドレス移行前の確認

- SSHでログインできる
- 画面共有でログインできる
- 自宅Wi-Fiの外からTailscale経由でSSH接続できる
- 再起動後にSSHとサーバアプリが復帰する
- ファイアウォール有効時も必要なサービスへ接続できる
- バックアップから必要なデータを復元できる

すべて確認してから、ディスプレイ、キーボード、マウスを取り外す。
